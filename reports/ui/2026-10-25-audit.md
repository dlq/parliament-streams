# Public Pages UI/UX audit — 25 October 2026

The Pages are useful for finding official viewing sources, and their restrained
visual identity and compact lists work well. They communicate the underlying
open source/data project less clearly. The highest-value changes are an explicit
explanation of the work, clearer coverage states and better map navigation.
The evidence does not call for a wholesale visual redesign or more animation.

## Scope and method

This combined usability, content and accessibility review covers the published
[Catalogue](https://dlq.ca/parliament-streams/),
[Legislatures](https://dlq.ca/parliament-streams/institutions.html),
[Coverage map](https://dlq.ca/parliament-streams/map.html) and
[Schedule](https://dlq.ca/parliament-streams/schedule.html).

Two tasks guided the review: finding an official broadcast/programme, and
understanding, reusing or contributing to the research and generated data.
The accessibility reference is WCAG 2.2 AA; this review is not a conformance
certification. Original screenshots were saved and inspected before findings
were accepted. All 25 captures appear below in journey order.

Captures use the in-app browser at 1440×1000, 390×844 and 320×800, with English
and a targeted German layout check. They show the published `50d6fa3` interface,
including a live schedule updated at 16:58 Toronto time, before the uncommitted
second EPG pass. Its newer parser/programme totals should not be read back into
these screenshots. No broadcast player was opened or played.

[Capture manifest](2026-10-25/manifest.json) records source, sizes and file hashes.
[Keyboard observation](2026-10-25/map-keyboard-observation.json) preserves the
measured map focus result. Code inspection supplemented captured behaviour; it
did not substitute for accessing the pages.

## What is working

- The dark green, restrained red, serif headings and ruled compact lists form a
  recognizable, coherent identity. Main navigation order is consistent once each
  page loads. Mobile rows/cards avoid a squeezed desktop table.
- Country search includes regional sources: Canada returns Alberta and British
  Columbia. Inventory grouping and exact catalogue links make research navigable.
- Evidence dates, identities, caption information and report links are available
  in details. The site distinguishes a play button from reuse permission.
- IPTV fields are selectable, copy buttons have distinct accessible names, and
  successful copying produces a polite status message. VLC instructions correctly
  distinguish opening a playlist from configuring XMLTV support in another app.
- Native inputs/disclosures, labelled controls, visible focus indicators, skip
  links, result announcements and explicit viewer-local time text provide a good
  accessibility foundation. On mobile, selecting Alberta focuses the detail
  heading; Escape closes the panel and restores the selected source button.
- The sampled mobile pages fit 390 pixels. The schedule fits 320 pixels and
  keeps Now/Next labels and timezone information visible. This is evidence of
  sampled reflow, not a complete zoom or text-resize assessment.

## Prioritized findings

### U1 — High: explain the project and expose data/code as a first-class route

**Evidence:** steps 1, 4, 5; captures 01, 05, 06, 07, 14. The catalogue introduces
finding video, then offers a single raw source JSON link. Playlists/XMLTV sit
inside an IPTV disclosure, inventory JSON inside Scope and method, and the
GitHub header link disappears on mobile. There is no shared explanation or
index connecting these products, their schemas, update process and evidence.

**Effect:** a visitor can use the directory without discovering that the main
project is reusable code and maintained/generated datasets. Someone seeking
data has to assemble the structure across unrelated controls and GitHub pages.

**Recommendation:** keep the compact viewing-first catalogue. Add one short
visible sentence such as “An open source project documenting legislatures,
official broadcasts and programme data,” with a consistent **Data and method**
route available from every page, including mobile. Explain:

1. Research inventory: bodies, chambers, authority and scope evidence.
2. Stream catalogue: documented official viewing sources linked to institutions.
3. Checks and review: access, identity, programme mapping and permissions are
   different findings; automation proposes changes for review.
4. Generated products: JSON, M3U/M3U8, XMLTV and the Pages views.

Give each asset its stable URL, purpose, schema/docs, update cadence, freshness,
coverage limits and reuse terms. Distinguish project/data licensing from source
broadcast rights. Link code and contribution guidance. The existing “Download
inventory JSON” goes to a GitHub file view: use a real download/raw endpoint or
label it “View inventory JSON.” A small diagram/table is sufficient; do not
place an implementation manual above the source list.

### U2 — High: make counts and eligibility describe the thing being counted

**Evidence:** steps 1, 5, 6, 9; captures 01, 06–08, 12–13. The live catalogue says
“Schedule sources: 37,” the schedule shows ten populated channels, and the
inventory shows 948 entries. All can be correct, but their relationship is
unexplained in the visible introduction. Green “Eligible” appears beside a
catalogue link or “Catalogue match not yet documented.”

**Effect:** parser connection can be mistaken for usable programme coverage;
institution eligibility can be mistaken for an approved or playable stream;
mixed institutions/chambers can be mistaken for a count of distinct parliaments.

**Recommendation:** state visibly that the inventory tracks legislative bodies
and chambers, while the catalogue tracks viewing sources. Define inventory
counts and label eligibility **Within research scope**. Separate “parser
connected,” “schedule events available,” and “XMLTV programmes available” in the
data/method explanation. Keep a concise, linked summary in the catalogue, using
actual populated coverage for a viewer-facing programme metric. Preserve the
user's always-visible coverage line. Generate these totals from the products;
do not hardcode audit figures or imply a 37-to-ten data loss.

### U3 — High: show map search results where the user is searching

**Evidence:** step 7; captures 09–11 and 18. Typing Alberta changes the index
below the map to one result, but the visible map and Canada sidebar remain
unchanged. At desktop size the result is below the viewport. On mobile the map
also precedes the selected sidebar and result index. Source inspection confirms
typing only rerenders that index; Enter selects the first match, with no nearby
instruction explaining this shortcut.

**Recommendation:** place a visible result list/count directly beside or below
search, announce its count, and provide an explicit select action. Selecting a
result should bring its details into view predictably. State whether search
filters jurisdictions or selects one; do not silently treat a partial query as
an instruction to open its first match. Keep the full text index as the usable
alternative to tiny map areas.

### U4 — High: repair map keyboard focus and reduce repeated tab stops

**Evidence:** step 8; captures 18, 24 and the saved keyboard observation. The
loaded graphic exposes **240 SVG tab stops** before the zoom controls and lower
index. Pressing Tab in search moves to the Canada map feature. Activating the
Alberta result with Enter selects it, but `document.activeElement` becomes BODY.
Source inspection confirms list replacement removes its focused button; zooming
the selected geography does not move DOM focus. The existing skip link lands
before the graphic, and no post-graphic shortcut or arrow-key navigation exists.

**Recommendation:** preserve/re-establish the selected list button or deliberately
focus a labelled result heading; announce the selection. Provide a direct route
from search to results/details. Use one well-designed keyboard entry to the map
with documented arrow-key behaviour, or make the native searchable index the
primary equivalent and remove redundant graphic tab stops. Do not describe the
current sequence as a keyboard trap: it is escapable, but excessively long.

W3C's [keyboard interface guidance](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)
explains efficient composite navigation. A final pattern must be verified with
keyboard and screen readers, including focus after filtering, selection and zoom.

Selected SVG features also lack `aria-pressed`/`aria-current`, unlike the native
index buttons. A current DOM check of the focused, selected Alberta polygon
found an outline style of `none`; selected and focused-selected CSS keep the
same fill/stroke. Preserve a distinct focus indicator and expose selected state
consistently. [Saved selected-focus observation](2026-10-25/map-selected-focus.json)
records the actual DOM result. Keep a non-colour selection cue as well.

### U5 — Medium: distinguish missing automation, no listings and source failure

**Evidence:** step 9; captures 12–13, 19. Alberta can be selected from a long
jurisdiction menu, then receives “No programme listings match these filters” and
a collapsed “Calendar / agenda · 1 source.” There is no nearby explanation of
whether collection exists, failed or returned no events. The schedule mixes
linear guides and institutional event directories under “Programme guide.”

**Recommendation:** use the existing machine-readable coverage states to show a
short, specific explanation and next action: no parser yet → official agenda;
source failure → collection date and official source; genuine empty window → no
published listings in this window; uncertain feed mapping → event information
available, outside linear XMLTV. Retained data should carry its age. Add Clear
filters and a relevant source/contribution link. Explain that Now/Next is a
summary, not the complete dated schedule; label event directories accurately.
Offer **Open official source** directly where playback is external, alongside
the catalogue/evidence link, avoiding an unnecessary intermediate page.

### U6 — Medium: keep translated navigation readable at narrow sizes

**Evidence:** step 12; captures 20–22. At 320 pixels English “Legislatures” splits
within the word; German “Gesetzgebende Körperschaften” breaks into four fragments
and “Abdeckungskarte” into three. No horizontal overflow was measured, but the
links become difficult to scan. The translated navigation's accessible name is
“Katalog” even on Schedule; the brand's German accessible name refers to About
while its link leads home.

**Recommendation:** give narrow navigation sufficient width per item using a
clear wrapping or accessible menu pattern, and review short native-language
labels with fluent speakers. Preserve full accessible names and a consistent
Primary navigation/Home meaning. Test all 23 locales at 320/390 pixels, text
resizing and 400% browser zoom; do not solve this by shrinking the text.
W3C's [reflow guidance](https://www.w3.org/WAI/WCAG21/Understanding/reflow)
is the reference for the 320 CSS pixel check. Broken words alone do not establish
a WCAG failure; practical legibility still needs fixing.

### U7 — Medium: simplify evidence terminology and separate permission questions

**Evidence:** step 3; captures 03–04 and 15. Alberta's detail panel repeats
“Official page” under Source type and Source kind, then shows Link-out, Page
only, Unknown and With conditions. The later validation section separately
reports Access status OK. “Use guidance” does not clearly announce permissions.

**Recommendation:** preserve evidence but group it around three questions:
**Where can I watch?**, **What was checked, and when?**, **What reuse is documented?**
For a link entry, a statement such as “Official viewing page checked on [date]”
is clearer than adjacent unexplained status badges. Rename the permission
disclosure **Reuse and permissions**, keep technical evidence separately
expandable, consolidate duplicate fields, and retain caption facts and evidence
links. Never convert technical success or absent prohibitions into permission.

### U8 — Medium: explain that IPTV exports are global and independent of filters

**Evidence:** step 4; captures 02, 05, 05b. Canada remains in the search field while
the global playlist links are displayed between filters and Canadian results.
Nothing visible states that those filters do not affect the downloads.

**Recommendation:** say **“These playlists cover all countries; page filters do
not change them.”** Display current playlist counts and explain “Always-on”
versus sitting-only streams and partial XMLTV coverage. Preserve working copy
feedback, selectable URLs, the `.m3u` compatibility links and the honest VLC guide
limitation. Do not build a new filtered-export feature just to resolve the wording.

### U9 — Medium: share contribution and project information consistently

**Evidence:** steps 1, 5, 10–11; captures 01, 06–07, 14, 16, 18–19. The inventory
has a prominent Help improve this list disclosure. Catalogue visitors mainly
see JSON/GitHub, and footers vary: About on Catalogue, attribution on Map, data
on Schedule, GitHub on Legislatures. On mobile GitHub disappears from the header;
the catalogue footer is after the full long list.

**Recommendation:** provide consistent, compact **Data and method**, **Contribute**
and **Code** utilities near task entry and in a shared footer. Reuse existing
issue templates for sources, corrections, metadata, guide parsers, accessibility,
translations, documentation and code. Keep “Help improve this list” and make the
same invitation available at a missing source or schedule state. Avoid loading
the four primary navigation items with a large new menu of project details.

### U10 — Low: tighten mobile entry and repeated labels

**Evidence:** steps 10–12; captures 14, 17, 19–21. The first catalogue row begins
around 735 pixels and the first filtered institution around 765 pixels in the
sampled 844-pixel viewport. Schedule cards repeat Now as both a section label
and a current-programme badge.

**Recommendation:** retain always-visible coverage and compact rows. Trim mobile
hero height and secondary spacing before adding another disclosure. Use one
clear current-programme marker per card. Keep source captions/accessibility
information discoverable through details without filling every compact row with
badges. This is refinement after structural and keyboard fixes, not a reason to
add animation or remove the visual identity.

## Implementation order and acceptance checks

1. **Map interaction/accessibility:** visible search results; predictable selection
   and focus; short keyboard route to the index/details. Test Enter, Space, Tab,
   Shift+Tab, filtered selection, zoom and narrow-screen result visibility.
2. **Shared explanation and copy:** a concise project/data route, defined lists
   and counts, global IPTV scope, consistent utilities/contribution paths. A
   newcomer should be able to identify the two canonical lists, obtain an asset
   and explain its limits without searching repository source.
3. **Coverage-aware schedule and details:** distinct, actionable coverage states,
   direct official viewing links and simpler evidence/permission wording. Check
   fixtures for no parser, empty window, source error, stale data, starts only,
   unverified feed mapping and populated linear guide.
4. **Responsive/localized refinement:** retain the compact lists and current
   identity, repair navigation wrapping, then check all supported locales and
   screen-reader/zoom/text-spacing behaviours. Do not add decorative motion to
   solve information architecture or task-discovery problems.

## Accessibility limits

Keyboard actions, native semantics, live-region attributes, focus movement,
control dimensions and sampled overflow were inspected in the current run.
Map zoom buttons measured 34×34 CSS pixels; main controls measured 32–44 pixels
high, so small typography alone is not evidence that these controls fail target
size. Tiny geographic features still need an equivalent usable list. W3C's
[minimum target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)
includes spacing/equivalent-control exceptions; do not call every small country
shape an automatic violation.

The separate EPG implementation checks passed HTML/browser/Axe tests. That
supports regression confidence but does not certify these journeys. This audit
did not run VoiceOver/NVDA, actual browser 200%/400% zoom, forced colours,
user text-spacing overrides, real iOS Safari, every translation, or actual video
caption/audio-description controls. No end-user usability interviews were run.
Hero contrast across every rotating background and nonvisual announcements
require further targeted checks. Source media accessibility and accessibility
of these Pages are separate responsibilities. Report these gaps explicitly
instead of presenting a clean automated scan as full WCAG compliance.
